## Problem Statement
GéoDam a trois modes de jeu et un profil local, mais la mission cartographe (compléter les ~20 000 barrages du registre ICOLD sans coordonnées) ne montre pas son effet : le joueur ne voit pas ce que sa contribution change.

## What Makes This Cool
« Cartographe de l'année » : une carte vivante qui se remplit au fil des contributions de la communauté, avec un tableau d'honneur par pays que l'on peut montrer à l'ICOLD.

## Constraints
- Cloudflare Workers + D1, démo GitHub Pages à serveur simulé : tout doit exister côté serveur réel ET côté démo.
- Pas de compte (pseudo seulement) ; confiance via étalons et consensus pondéré.
- Données ICOLD sous autorisation : la carte ne doit exposer que ce qui est déjà publié dans le dépôt.

## Premises
1. Le levier principal est la complétion des barrages sans coordonnées via la mission cartographe.
2. Les premiers joueurs utiles sont la communauté ICOLD.
3. Le projet reste sans compte.
4. La prochaine amélioration réduit l'effort de contribution et rend l'effet visible avant tout nouveau mode de jeu.

## Approaches Considered
### Approche A : Minimale (S, risque faible)
Source prérenseignée dans la mission cartographe + jauge d'accueil. Écartée : n'ajoute pas de raison de revenir.
### Approche B : Équilibrée (M, risque moyen)
Carte vivante, notification d'impact (« ton avis a fait passer X à prêt à vérifier »), page d'honneur par pays. Réutilise le consensus pondéré, l'export CSV admin et le profil local.
### Approche C : Comités ICOLD (L, risque élevé)
Tableau de bord pour les comités nationaux. Écartée pour l'instant : suppose des rôles, hors du modèle sans compte.

## Recommended Approach
Approche B : rend visible l'effet de chaque contribution, ce qui fidélise, sans changer l'architecture.

## Open Questions
- Que peut-on afficher publiquement sans dépasser l'autorisation ICOLD (noms de barrages, coordonnées candidates) ?
- La notification d'impact fonctionne-t-elle sans compte (identifiant local du profil, ou passage au prochain lancement) ?
- Comment la démo GitHub Pages simule-t-elle la carte vivante sans données partagées ?

## Success Criteria
- Un joueur voit, après sa contribution, l'état du barrage concerné (nombre d'avis, passé à « prêt à vérifier » ou non).
- La carte vivante affiche la progression par pays et se met à jour sans rechargement manuel.
- Les tests existants (navigateur, CI qualité) restent verts.

## Distribution Plan
Le pipeline de déploiement existant (Workers + D1, Pages pour la démo) couvre ce changement ; ajouter une migration D1 si nécessaire.

## Next Steps
1. Ajouter une API de lecture (`/api/contributions/progress`) par pays, côté serveur et démo.
2. Construire la carte vivante sur la page « Le registre ».
3. Notification d'impact après la manche (réponse API enrichie).
4. Page d'honneur par pays.
5. Tests navigateur et revue avec `/plan-eng-review`.
